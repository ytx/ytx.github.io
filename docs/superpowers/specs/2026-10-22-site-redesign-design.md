# ytx.github.io 再構成 設計書

日付: 2026-10-22
状態: レビュー済み（本人の承認待ち）

## 1. 目的と背景

ytx.github.io は本人のメモ置き場であると同時に、講義の受講者や仕事相手が「作ったもの」を見に来る名刺でもある。現状は Lume の最小構成で、講義資料とメモが数本あるだけで、作品を見せる構造も記事の分類も見た目の整えもない。

今回、現在の内容と構成をすべて破棄し、次を満たすサイトとして作り直す。

- 作品（ポートフォリオ）を見せる。スクリーンショット、デモ動画、リンク、使い方の記事。
- マークダウンで記事を書き、カテゴリ（親子 2 段）で分類する。
- main に push したら自動で公開される。
- やわらかいデザイン。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
- トップページを開いた人が、作品のビジュアルで引き込まれ、作品ページか記事にたどり着ける。
- 作品を追加するとき、マークダウン 1 ファイルと画像を置くだけで済む。
- 記事を追加するとき、マークダウン 1 ファイルを置き、frontmatter にカテゴリを書くだけで済む。
- push から公開まで人手が要らない。

### 非ゴール（今回はやらない）
- サイト内検索、コメント、ダークテーマ、多言語（日本語のみ）。
- 既存コンテンツ（`f/`, `s/`）の移行。破棄する。必要になれば後から記事として書き直す。
- アプリ本体の開発やホスティング。アプリは各自のリポジトリで公開する（§6）。

### アンチゴール（こうなったら失敗）
- 技術ブログのような硬い見た目。
- 作品が記事の中に埋もれ、トップから見えない。
- 作品やアプリを増やすたびにサイト側の設定をいじる必要がある。

## 3. 読者と使われ方

- 本人: 記事を書く、作品を登録する。
- 受講者・仕事相手: 作品を見る、使う、使い方の記事を読む。
- トップ → 作品ページ → アプリ本体 / 使い方記事、という流れが主動線。

## 4. 道具と構成

### 4.1 静的サイトジェネレータ
**Astro** を使う。理由: 作品カード、キャッチ、カテゴリ一覧といった部品を自作するサイトなので、コンポーネントで組める道具が一番素直。記事と作品をコンテンツコレクションとして型付きに扱える。Deno + Lume からの乗り換えは本人了承済み。

- Node LTS、パッケージマネージャは npm。
- TypeScript。
- CSS は Astro のスコープ付き CSS と、グローバルのデザイントークン（CSS 変数）。CSS フレームワークは使わない（やわらかさを自前で制御するため）。
- Astro 組み込みの画像最適化（`astro:assets`）を使う。

### 4.2 リポジトリ構成（目安）
```
.
├── .github/workflows/deploy.yml   # Astro 公式手順で Pages へ
├── astro.config.mjs
├── package.json
├── public/                        # favicon など、加工しない静的ファイル
├── src/
│   ├── content.config.ts          # コレクション定義（works, blog）
│   ├── content/
│   │   ├── works/<slug>/index.md  # 作品（日本語）。同フォルダに index.en.md と画像
│   │   └── blog/<slug>.md         # 記事（日本語）。英語版は <slug>.en.md
│   ├── data/categories.ts         # カテゴリ定義（日英の表示名）
│   ├── i18n/                      # 定型文の辞書 ja.ts / en.ts とヘルパー
│   ├── components/                # Hero, WorkCard, PostCard, CategoryPills など
│   ├── layouts/
│   ├── pages/
│   └── styles/tokens.css          # デザイントークン
└── docs/superpowers/specs/        # この設計書
```
現在の Lume 関連ファイル（`_config.ts`, `_cms.ts`, `_data.yml`, `_includes/`, `deno.json`, `styles.css`, `f/`, `s/`, `index.md`, `.github/workflows/lume.yml`）はすべて削除する。

### 4.3 公開
- main への push で GitHub Actions が `astro build` し、`actions/upload-pages-artifact` + `actions/deploy-pages` で公開する（Astro 公式ドキュメントの GitHub Pages 手順に従う）。
- GitHub Pages の Source は「GitHub Actions」。
- `site: "https://ytx.github.io"`、`base` は設定しない（ユーザーサイトなのでルート配信）。

## 5. コンテンツモデル

### 5.1 作品（`src/content/works/<slug>/index.md`、英語版は同フォルダの `index.en.md`）
```yaml
title: simplePages
summary: ブラウザだけで動く、やさしいメモ帳。   # 一覧カードとキャッチに使う 1 行
type: app | web                               # app: このドメイン配下で直接使う, web: 外部サイト
url: https://ytx.github.io/simplePages/       # 「使ってみる」「サイトを見る」の遷移先
repo: https://github.com/ytx/simplePages      # 任意
thumbnail: ./simplePages/thumb.png            # 一覧カード用。必須
screenshots:                                  # 任意、複数
  - ./simplePages/01.png
youtube: VIDEO_ID                             # 任意。YouTube の動画 ID
featured: true                                # 任意。トップのキャッチ候補
order: 10                                     # 任意。一覧の並び（小さい順、未指定は末尾）
parent: simplepages                           # 任意。親作品の slug。指定すると「親作品に含まれるページ」になる
tags: [memo, pwa]                             # 任意
published: 2026-01-01
```
本文（マークダウン）は作品ページの説明文になる。画像はコレクション内の作品ごとのフォルダに置き、相対パスで参照する（Astro の `image()` スキーマで最適化）。

**親子作品**: simplePages のように「まとめ 1 件 + 中の各ページ」を両方持ちたい作品は、まとめを通常の作品、各ページを `parent:` 付きの作品として登録する（1 段のみ。孫は作らない）。
- 作品一覧とトップの Works グリッドには親（`parent` なし）だけを出す。親カードには含むページ数のバッジを出す。
- 親の作品ページには、本文の下に子作品のカード一覧（thumbnail、title、summary、各自の url への「使ってみる」）を出す。
- 子作品も自分の作品ページ（`/works/<slug>/`）を持ち、パンくずで親に戻れる。`featured: true` は子にも付けられ、キャッチには子単体で出る。
- `parent` が存在しない slug を指したらビルドを失敗させる。

### 5.2 記事（`src/content/blog/<slug>.md`、英語版は `<slug>.en.md`）
```yaml
title: 記事タイトル
description: 一覧カードに出す要約
category: car/maintenance        # 親/子。親のみ (car) も可
work: simplePages                # 任意。作品の slug。指定すると作品ページに「使い方」として並ぶ
thumbnail: ./xxx/thumb.png       # 任意。無ければカテゴリ色の無地サムネイル
published: 2026-10-22
updated: 2026-10-23              # 任意
draft: false                     # true は本番ビルドから除外
```

### 5.3 カテゴリ（`src/data/categories.ts`）
コードで定義する。slug、表示名、親、テーマ色（カード無地サムネイル用）を持つ。初期値:

| slug | 表示名 | 子（例） |
|---|---|---|
| gadget | ガジェット | |
| car | 車 | maintenance: メンテナンス |
| travel | 旅行 | |
| diy | DIY | |
| howto | 使い方 | 作品の使い方記事用。`work:` 指定の記事はここに置くのを基本とする |

表示名は日英両方を持つ（`name: { ja: "車", en: "Car" }`）。子カテゴリは必要になったときに追加する。記事の `category` が未定義の slug を指したらビルドを失敗させる。

### 5.4 日英対応（Astro 標準の i18n ルーティング）
- 日本語が既定で `/`、英語は `/en/` 以下に同じ構造で置く（例: `/en/works/green/`、`/en/blog/car/<slug>/`）。
- **記事**: `blog/<slug>.md`（日本語）と `blog/<slug>.en.md`（英語）。同じ slug で対にする。英語版が無い記事は、英語サイトの一覧に「日本語」バッジ付きで出し、記事ページでは冒頭に「この記事は日本語のみです」と断って日本語本文を表示する（隠さない。私の判断。隠す方がよければ設定一つで切り替えられるようにする）。日本語版が無い英語のみの記事も同様に扱う。
- **作品**: `works/<slug>/index.md`（日本語）と `index.en.md`（英語）。url、repo、画像、youtube、featured、order、parent、tags、published などの共通項目は日本語側に書き、英語側には title、summary、本文だけを書く（共通項目が英語側に無ければ日本語側から引き継ぐ）。英語版が無い作品は記事と同じ扱い。
- **定型文**: ヘッダー、ボタン、セクション見出し、日付書式、404 文言などは `src/i18n/ja.ts` と `en.ts` の辞書から引く。カテゴリ名は §5.3 の両言語名を使う。
- **About**: `about.md` と `about.en.md` の 2 ファイル。
- **切替**: ヘッダー右端に「EN / 日本語」の切替リンク。同じページの対訳があればそこへ、無ければその言語のトップへ飛ぶ。各ページに `hreflang` を出す。
- **RSS**: `/rss.xml`（日本語）と `/en/rss.xml`（英語）。サイトマップは両言語を含む。
- フォント: Zen Maru Gothic は英字も含むので、英語ページでも同じフォントでよい。

## 6. アプリの公開方式（このリポジトリの外）

simplePages のような「直接使う」アプリは、**各アプリ自身のリポジトリの GitHub Pages**（プロジェクトサイト）で公開する。`https://ytx.github.io/<リポジトリ名>/` で配信され、このサイトからはリンクするだけ。コピーは持たない。

各アプリ側で必要なこと（この設計書の範囲外だが、慣例として記す）:
- Pages を Actions ソースで有効化し、ビルドしてデプロイするワークフローを置く。
- ビルドの `base`（公開パス）を `/<リポジトリ名>/` にする。

これにより、アプリの main に push すれば数分後に公開され、このサイトは再ビルド不要。

## 7. ページ構成

### 7.1 トップ `/`（ショーケース型、1 カラム）
1. **ヘッダー**: サイト名「ytx」、ナビ WORKS / BLOG / ABOUT。
2. **キャッチ**: `featured: true` の作品を一つ大きく見せる。左に画像（`youtube` があれば YouTube 埋め込み、無ければ `thumbnail`）、右に title、summary、ボタン（type=app なら「使ってみる」、web なら「サイトを見る」）と作品ページへのリンク。複数 featured があれば数秒ごとに自動で切り替える（ドット表示付き、手動切替可）。
3. **Works**: 作品カードのグリッド（thumbnail、type バッジ、title、summary）。最大 8 件 + 「すべての作品」リンク。
4. **Blog**: カテゴリの絞り込みピル（すべて / 親カテゴリ）と最新記事カード 6 件 + 「記事一覧」リンク。ピルはクライアント側で絞り込む（ページ遷移なし）。絞り込みの対象は「全記事」で、ビルド時に「すべて」と各親カテゴリそれぞれの最新 6 件を HTML に出しておき、ピルで表示を切り替える（表示済み 6 件の中から絞るのではない。記事が増えても空になるピルが出ないようにするための私の判断）。記事が 0 件の親カテゴリはピル自体を出さない。
5. **フッター**: © ytx、GitHub へのリンク。

### 7.2 作品一覧 `/works/`
全作品のカードグリッド。`order` → `published` 降順。

### 7.3 作品ページ `/works/<slug>/`
title、summary、主要ボタン（使ってみる / サイトを見る）、repo リンク、YouTube 埋め込み（あれば）、スクリーンショット（あれば、横並び or 縦積み）、本文、子作品のカード一覧（親の場合、§5.1）、末尾に「使い方」として `work: <slug>` の記事カード一覧。

### 7.4 記事一覧 `/blog/`
全記事カード、published 降順。上部にカテゴリピル（親子をツリー表示）。

### 7.5 カテゴリ一覧 `/blog/<parent>/`、`/blog/<parent>/<child>/`
そのカテゴリ（親は子を含む）の記事カード一覧。パンくず付き。

### 7.6 記事ページ `/blog/<parent>/<child>/<slug>/`（子がない場合は `/blog/<parent>/<slug>/`）
パンくず、title、日付、カテゴリバッジ、本文、末尾に同カテゴリの記事 3 件。本文のコードブロックはシンタックスハイライト（Astro 標準の Shiki、やわらかい配色のテーマを選ぶ）。`work:` があれば冒頭に作品へのリンクカード。

### 7.7 About `/about/`
プロフィール（名前、肩書き、写真、短い自己紹介）、連絡先・SNS リンク。内容は本人が後から書く。マークダウン 1 ファイル（`src/pages/about.md` 相当）で編集できること。

### 7.8 その他
- 404 ページ（同じトーンで）。
- RSS（`/rss.xml`、記事のみ）とサイトマップ。Astro 公式インテグレーションで低コストに付く。

## 8. デザイン

本人が手本として挙げたサイト（日本のライフスタイル系ブログ、白地・角丸カード・大きな画像）の空気感を、作品主役の構成に移植する。ブラウザのモックアップで選ばれた方向は **「クリーム × テラコッタ」**。

### 8.1 トークン（初期値、builder が調整可）
- 背景: クリーム `#fff9f2`。カード面: 白 `#ffffff`。
- 文字: `#4a3f36`。薄い文字: 同色の 60% 程度。
- アクセント（見出し、ボタン、リンク）: テラコッタ `#c9744f`。
- サブアクセント: 芥子 `#e6c35c` 系、淡い緑 `#e4e7cf` 系（カテゴリ色やグラデーションに）。
- キャッチ背景: 桃 `#fbe3d3` → クリーム黄 `#f8ecc9` の斜めグラデーション。
- フォント: 本文・見出しとも **Zen Maru Gothic**（Google Fonts）。英字はそのままでよい。
- 角丸: カード 12〜16px、ボタン・バッジは pill（999px）。
- 影: 薄く柔らかい（`0 1px 4px rgba(0,0,0,.05)` 程度）。線より影と面の差で区切る。
- 余白はたっぷり。本文の行間 1.8 程度、最大幅 720px 程度。

### 8.2 やってはいけない
- 現サイトのようなダーク背景、角ばった枠、濃いグラデーション。
- 見出しの片側だけに太い色帯を付ける装飾（モックアップでは使ったが本番では避ける。下線や小さなマーカーなど別の方法で）。
- 絵文字の多用、派手なアニメーション。キャッチの自動切替はフェードで静かに。

### 8.3 レスポンシブ
スマートフォン幅で 1 カラムに畳む。作品グリッドは 4 → 2 → 1 列。キャッチは画像の下に文字。

## 9. 制約
- ホスティングは GitHub Pages のまま。サーバー処理なし（言語の自動判定もしない。訪問者は切替リンクで選ぶ）。
- 動画はリポジトリに入れない（YouTube 埋め込み）。画像は入れる。
- ローカルでプレビューできること（`npm run dev`）。

## 10. builder に任せること
- Astro のバージョン、ディレクトリの細部、コンポーネント分割。
- カテゴリ絞り込みピルの実装方式（小さな素の JS で十分）。
- YouTube 埋め込みの軽量化（サムネイルクリックで読み込む lite 方式など）。
- RSS・サイトマップ・OGP の具体。
- サンプルコンテンツ: 作品 3 件（下表）と、記事をカテゴリごとに 1〜2 本（ダミー文）。本人が後から差し替える。英語版は作品全件と記事 1 本だけ用意し、「英語版が無い記事」の表示も確認できるようにする。

| slug | title | type | url | 仮画像（`tmp/` のスクリーンショット、取得順） |
|---|---|---|---|---|
| green | green（happy green tiles） | web | https://green.sv4.me/ | 1 枚目（12.55.49） |
| kaji0 | kaji⭕️ | web | https://kaji0.trusted-host.online/ | 2 枚目（12.56.41） |
| simplepages | simplePages | app | https://ytx.github.io/simplePages/（仮。公開後に本人が直す） | 3 枚目（13.00.50）を thumbnail に流用 |
| l-timer | l_timer | app | https://ytx.github.io/simplePages/l_timer/（仮） | 3 枚目（13.00.50）。`parent: simplepages` |
| weather | weather | app | https://ytx.github.io/simplePages/weather/（仮） | 4 枚目（13.01.43）。`parent: simplepages` |

  - 画像は `tmp/` から `src/content/works/<slug>/` へ ASCII 名（`thumb.png`, `01.png` …）で移し、`tmp/` は削除する。いずれも約 1867×970（16:9 弱）なので、カードとキャッチの画像枠は **16:9** を基準にする。
  - simplePages は親子作品（§5.1）のサンプルを兼ねる。親 simplepages と子 l-timer、weather の 3 件を登録する。
  - summary は仮文で可（green: 「タイルで管理する、やること・記録・タイマー」、kaji⭕️: 「家事の記録と分担」、simplePages: 「ブラウザで動く小さなページ集」、l_timer: 「講義用の 2 段タイマー」、weather: 「天気」。本人が後で直す）。

## 11. 決定の記録
- 道具: Lume → Astro に乗り換え（本人了承）。
- トップ構成: 3 案からショーケース型（B）を選択。
- 見た目: 3 案からクリーム × テラコッタ（3）を選択。
- アプリ公開: 「成果物をこのリポジトリへコピー」から「各リポジトリの GitHub Pages で公開、ここはリンクのみ」へ変更（本人了承）。
- 動画: YouTube 埋め込み。
- 日英対応: 4 案（URL で分ける / 作品と定型文のみ / 1 ページ内切替 / 機械翻訳）から「URL で分けて全部対応」を選択（本人）。
- simplePages: 「まとめ 1 件と各ページの両方を持つ」（本人の要望）→ `parent:` による 1 段の親子作品として設計。
- 私（Claude）の判断として入れたもの: 親子作品の見せ方（一覧は親のみ、親ページに子カード、子も単独ページを持つ）、featured による自動切替キャッチ、`work:` による作品と記事の紐づけ、検索・コメント・ダークテーマを初回に入れない、未翻訳ページは隠さず断り書き付きで出す、RSS とサイトマップを付ける、howto カテゴリ。
